# ReID 界面与逻辑审核 · 2026-09-05

按用户要求实际调用本机 Fable5 wrapper（`claude-fable-5`）两次，分别进行界面源码审查和聚焦逻辑审核。
仅读取相关源码，没有给它生产操作权限，也没有提供历史图片、数据库或凭据。建议经主代理复核并补充
回归用例后落地。本记录是源码及合成数据测试结论，不是截图验收，也不是现场准确率报告。

## 界面采纳

- 新增纯展示组件 `ReidEvidenceSummary.vue`，统一普通候选和跨摄像头候选的时间、结论及证据明细。
- 首层保留查询/候选图、人体相似度、时间、一句判断；标签、人脸、融合分和完整 crop ID 收进原生
  `details`，默认折叠。人工标注按钮保持独立可操作，标注仍只用于校准，不改身份绑定或在线排序。
- “去过哪些门”改为“跨摄像头线索”，“匹配结果”改为“检索候选”。机器输出明确为待核对，只有真实
  人工标注才能显示“人工已确认”。没有把 `beats_chance` 当作到访事实。
- 人脸余弦和质量指数用 `0.45` / `0.80` 形式显示，不渲染成“45% 是同一人”。标签一致比例仍以有明确
  分母的形式展示，例如“高置信标签一致 3/4 · 加权一致 75%”。缺失证据保持未知。
- 图片统一画框、等高 `object-fit: contain`，不裁掉原图；取消结果列表的小内滚动区；窄屏查询栏不再
  sticky 遮挡候选；放大预览补齐关闭按钮聚焦、Tab 约束及关闭后焦点恢复。

## 已复现并修复

1. 上传图与旧 `crop_id` 的线索、标题和反馈混用。现在以当前查询模式为准，并在切换时清空旧线索；
   请求带上下文代次，迟到响应不能覆盖新查询，A → B → A 也不会复活旧响应。
2. 较慢的反馈 GET 可能覆盖刚保存的人工判断。现在保留当前上下文中更新的本地已保存记录。
3. 摄像头分组按 `fusion_score` 二次排序，丢失后端的人脸优先层级。现在按后端结果的首次出现顺序分组，
   保留每个摄像头内部的返回顺序；没有改候选配额。
4. 单个高置信标签虽然不显示一致徽章，却仍在后端产生加减分与 tie-break。现在不足 2 个可比标签时两处
   均中性；至少 2 个可比标签后的连续加权、冲突数量/权重/时间窗硬门保持原有设置。
5. 多帧查询只取最高质量人脸时，身体相近的旁人可替换所选图身份，误杀真目标。合成正交人脸向量用例已
   复现。现在以明确所选 crop 为身份锚点，可测源脸会拒绝不相符的替代脸；源脸不可靠时，借来的邻帧脸
   只参与软加权，不获得强匹配豁免或硬排除权。有效同人清晰邻帧仍可提升比较质量。

上述更改沿用 FastAPI 服务分层，身份关联放在 face service、强证据资格放在 fusion service，没有引入
新的业务 API、模型、数据迁移或阈值。

## 没有直接采纳的建议与限制

- Fable5 建议新增“负向但保留”阈值或向普通结果返回硬排除项。本轮没有采纳：未经现场真值校准调整阈值
  会扩大误匹配风险，也违背用户不希望明显不同的人混入结果的要求。仅修正文档中“False 不删除”的旧注释。
- 被硬排除候选仍没有专门的审核池，误杀率存在评估盲区；应后续设计独立审核视图，不能混进普通命中列表。
- 多帧人体聚合本身仍依赖身体向量阈值，不能保证同款衣着的人绝不混入。此次修复堵住了借脸引发的强身份
  决策风险，不代表完成了多人轨迹真值验证；背影查询可能因此减少强人脸确认，这是有意的保守取舍。
- 无人工真值集，不报告准确率提升百分比；仍需多人跨摄像头走测评估召回、误报、硬过滤误杀和阈值。
- 当前 Python 环境未安装 mypy、black、pytest-cov；不能将 Ruff/pytest 通过写成严格类型检查或覆盖率验收通过。
- 自动化浏览器此前多次导航失败，LAN HTTP 可达不等于用户页面可见。本轮组件渲染/状态回归与构建检查
  不替代桌面、窄屏的实际浏览器视觉验收。
