# 查询正确性与可回退发布（2026-09-15）

## 本次边界

- 修复带时区的查询时间与 SQLite 本地时间存储不一致的问题；无时区输入仍按 `LOCAL_TIMEZONE` 解释。
- 布尔标签支持明确的否定条件，例如“不戴眼镜”“没有背包”。未知值不等于否定；互相矛盾、暂不支持的否定或“或”条件返回 400，而不是静默忽略。
- 抓拍列表的标签关键词按属性值匹配，不再因为 JSON 中存在 `backpack` 等字段名就命中。
- 人脸诊断使用 `POST /api/face/diagnostics/crops`，每批 1–100 个 crop UUID。只诊断请求指定的抓拍；缺失 ID 跳过，不回退到最近抓拍。
- 列表先显示，再异步加载当前页诊断；翻页时取消旧请求并丢弃过期响应。诊断失败不清空列表。
- 未注册的 `/api/*`、`/v1/*` GET 返回 JSON 404，不再落入前端 HTML。
- 保留服务器已有的 VIP、到访统计、ReID 跨镜候选覆盖、属性回填游标和完整人体过滤能力，并同步到版本库，避免发布时覆盖丢失。

本次不更换模型、不重建历史向量、不批量回填、不改身份归属、不修改现有登录凭据。结构化检索不是任意自然语言推理；没有已知标签的描述仍不能保证有结果。

## 验证门槛

```bash
.venv/bin/python -m pytest -q
npm --prefix frontend run test:search
npm --prefix frontend run test:observations
npm --prefix frontend run test:reid
npm --prefix frontend run build
```

另需用本次后端生成的 OpenAPI 执行前端 `check-api.mjs`，验证客户端调用契约。可选 ReID 图像测试需要本地 OpenCV、Matplotlib 等模型运行依赖；跳过必须记录原因，不能当作通过。

服务器验收使用数据库快照并关闭 lifespan，避免预发布启动流处理、向量队列或属性队列。模型服务保持原进程。预发布媒体路径只读，数据库写入仅允许快照。

| 检查 | 通过条件 |
| --- | --- |
| 时区 | 同一时间窗口的本地无时区、`+08:00`、`Z` 表达返回相同 crop ID |
| 否定 | 所有命中都有明确 false 证据，无 true、unknown 或冲突证据 |
| 标签列表 | “背包”只命中 true；total 和分页来自相同谓词 |
| 日期错误 | 开始晚于结束在页面提示，后端返回 400 |
| 人脸诊断 | 第二页 ID 与请求一致；不请求无关的最近 100 条 |
| 接口边界 | 未知 API 返回 JSON 404；已注册 API 正常 |
| 现有业务 | 上传校验、已有抓拍/图片、人脸库、ReID 查询可用，原运行流恢复 |
| 性能 | 在相同数据量及机器负载下重复采样；列表/结构化查询 p95 不超过 2 秒且不超过发布前同类请求的 2 倍。达不到时先不切主服务 |

结构化抓拍筛选目前按稳定顺序分批读取观察索引，内存有界，但统计 total 需要扫描匹配范围。数据持续增长后应将谓词下推数据库或增加专用索引；不能宣称该路径已适用于百万级数据。

## 已有 systemd 实例的发布路径

已有实例继续使用 systemd，本次不混入 Docker Compose 迁移：

1. 以已推送的 Git commit 打包代码和对应的 `frontend/dist`，排除 `.env`、数据库、媒体、模型、虚拟环境和 `node_modules`。
2. 解压到现有应用根目录下的 `releases/<commit>`，写入 `RELEASE_REVISION` 和校验清单。
3. 在服务器本地保存原 unit/drop-in、配置权限受限副本及 SQLite 一致性备份；不把数据或密钥传回开发机。
4. 使用独立快照、回环端口、只读生产媒体和 `--lifespan off` 运行预发布。禁用 GPU、ReID、VLM、向量索引及流自动启动；预发布只验查询与页面逻辑。
5. 通过 API unit 的专用 drop-in 设置 `--app-dir <release>`，保留原 WorkingDirectory、EnvironmentFile、虚拟环境、监听端口。仅重启 API，不重启独立 ReID 或 VLM。
6. 验证实际进程参数、健康、真实 API、页面静态资源、已有数据和原运行流，记录 commit 与时间。

## 回退

- 若健康检查失败、查询语义回归、原运行流未恢复、错误率升高或性能越界，恢复此前 API drop-in，执行 `daemon-reload` 并仅重启 API。
- 数据库只做兼容性加列与索引维护；不能通过恢复旧数据库来回退代码，否则会覆盖发布后新产生的数据。恢复数据库属于独立人工确认操作。
- 不删除旧代码、快照或模型；先完成观察期再单独安排清理。
- 认证加固和跨服务凭据轮换需另行协调调用方；本次不突然开启认证而中断已有接入，也不将无认证访问视为已解决。
